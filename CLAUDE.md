# Amber — project notes

Windows blue-light filter. C# / WPF on .NET 10, targets Windows 10 and 11 (x64).

## Decisions
- **Tint engine:** Magnification API `MagSetFullscreenColorEffect` (5×5 color matrix, no admin, no overlay). Always reset to identity on every exit path. Tested: Windows also clears the tint if the process is killed; tint survives lock/sleep; cursor is not tinted.
- **UI:** fully custom design from Figma (file `yq4CMAFmPnS3ZclM1kvkAy`, pages "Design 1.0" and "Components"). Light theme only. Styles and icon geometry live in `Theme.xaml`.
- **Font:** Plus Jakarta Sans (SIL OFL, bundled; license in `Licenses.txt`). Figma uses Satoshi, whose license doesn't allow bundling — don't switch back.
- **Window:** standard Windows title bar, 692 px wide; 433 px tall, 545 px while the schedule times are shown.
- **Time picker:** hour + minute dropdowns (5-minute steps), plus an AM/PM box only when Windows uses a 12-hour clock. Design polish comes later.
- **Motion:** hover/selected looks fade in 0.3 s (VisualStateManager animating Opacity of layers); the switch knob slides. Keep motion to states, not everything.
- **Priorities:** lightweight, minimal CPU/memory, simple code. App lives in the tray; window is optional.
- **Tray:** own `Shell_NotifyIcon` interop (no WinForms). Double-click opens the window; right-click menu: Turn on/off, Open Amber, Quit. Grey icon when off. Icons are generated by `tools/make-icons.ps1`.
- **Window lifecycle:** closing the window destroys it (Amber keeps running), then memory is released. Measured (Release, Task Manager "Memory"): idle in tray settles at ~3.2 MB (never opened) / ~4.1 MB (after the window was opened); ~42 MB with window open. Owner's budget: 5–6 MB idle.
- **Startup:** `--tray` argument = start without a window (for start with Windows). Single instance; a second launch shows the existing window.
- **Settings:** `%AppData%\Amber\settings.json`.
- **Schedule (step 4):** fixed start/end time for the selected mode. Tint fades ~5 s at start/end; the ON/OFF button fades 0.5 s. Manual OFF inside the scheduled hours lasts until the next start time; manual ON outside them lasts until the next end time. Starting Amber (or waking the PC) inside the scheduled hours turns the tint on with the fade.
- **Mode/intensity changes** never turn the tint on; only the ON/OFF button does.

## Working agreement
- The owner is not a developer: explain steps plainly, keep changes small, one plan step per branch.
- Don't start the next plan step until the owner has checked the current one.
- The owner often has Amber running, which locks `bin\`. Build/test with `--artifacts-path` pointing to a temp folder.
- Never launch Amber with the owner's real settings (it may tint their screen). Back up `%AppData%\Amber\settings.json`, use a copy with `"IsOn": false`, restore afterwards.
- CI: GitHub Actions (`.github/workflows/ci.yml`) builds and runs tests on every push.
